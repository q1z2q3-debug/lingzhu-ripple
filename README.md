# 涟漪认知场 · 灵助落地包

> 定位一句话：**不做"又一个问答助手"，做灵助运维域/质量域所有助手共用的"判断内核"。**

灵助已经提供知识问答、规则检查、异常诊断、方案推荐等能力；它缺的不是"再会说话一点"，
而是**判断能不能被复核、经验能不能被复用、不确定性能不能被量化**。
本包补的正是这三件：把设备/工艺状态压成一个 9 维三态构型（19683 种），
在概率场上做漂移-扩散推演得到可解释的态势，再经因果免疫层给根因，最后由闸门决定"能不能派单"。

- 仓库：https://github.com/q1z2q3-debug/lingzhu-ripple
- 在线方案页（GitHub Pages，源 main:/docs）：https://q1z2q3-debug.github.io/lingzhu-ripple/
- 本地直开：`灵助落地一页.html`（单文件、零外链依赖，双击即用）

## 2. 三分钟跑起来

```bash
python3 mcp/ripple_mcp_server.py --selftest     # 10 项自检，应全部 ok
python3 demo/demo_run.py                        # 运维域 7 段业务线，12/12 通过
python3 demo/demo_quality.py                    # 质量域追溯 + 沙盘
```

环境：Python 3.9+、numpy。数据目录由 `RIPPLE_DATA_DIR` 指定（默认 `./data`）。

## 3. 接入灵擎（四层，逐层可独立验收）

1. **MCP 工具层**：`python3 mcp/ripple_mcp_server.py`，stdio 传输，无需改造网络。
2. **Skills 层**：`skills/` 三个手册定义"何时调、调哪个、怎么解读、什么时候必须停"。
3. **多 Agent 层**：`agents/` 定义诊断 / 根因追溯 / 态势研判三岗 + 仲裁，共用同一内核与同一份因果库。
4. **工作流层**：`workflows/` 把"点检 → 诊断 → 派单 → 回填 → 学习"接成闭环。

## 4. 已实测的硬指标（本机，单线程）

| 指标 | 实测 | 说明 |
|---|---|---|
| 单步场演化 | **1.75 ms** | 19683 维全场更新，核函数可分离为 9 次一维卷积 |
| 一次完整诊断（映射+演化+因果+闸门+工单） | **≈ 12 ms** | 含 6 步证据整合 |
| 场熵（稳态） | **1.8–2.0**（上界 9.88） | 非平凡稳态，既非热寂也非坍塌 |
| 驻波比（top10 质量） | **0.87** | 有明确吸引子，"说不清"时可量化 |
| 免疫查询 | **< 0.5 ms** | 双通道（文本 0.55 + 拓扑 0.45） |
| 正常设备误告警 | **0**（全维非负直接放行） | 不产生告警疲劳 |
| 空知识库时的编造 | **0**（强制中和转人工） | 自检项已固化 |

## 5. 边界（先讲清，避免落地后返工）

- **不做预测**：只做"当前构型 + 已见根因 + 不确定性"，预警是趋势维（变）的推论，不承诺具体失效时刻。
- **不替代大模型**：大模型负责语言与方案生成，本内核负责"判断是否有据、是否可派单"，是校验层与沙盘层。
- **不做玄学**：卦象只是 9×3 状态的编码与可读命名，不参与因果，不做占卜式推断。
- **需要标定**：`inspection_mapper.py` 的阈值必须按客户设备与工艺重新标定，这是唯一主观环节，也是精度上限所在。
- **必须人机闭环**：`verified=false` 的经验不会获得派单权限，只进候选。
- **算力要分片**：500 路以上必须按设备分片，不要用一张场承载全场设备。
