# Skill：涟漪态势研判（跨域通用 / 看板与例会）

> 适用助手：所有域的管理驾驶舱、班前会助手、值班长助手。
> 定位：不诊断单台设备，回答"整条线/整个域现在稳不稳、要不要干预、干预什么"。

## 触发条件

- "现在产线什么状态""今天有什么风险""要不要调整排产"；
- 例会/日报/周报需要态势段落；
- 看板需要"确定性指标"（不是告警条数）；
- 用户要求"先演练一下改了会怎样"。

## 可用工具与用法

| 工具 | 用法 | 输出读法 |
|---|---|---|
| `ripple_field_status(tick=true)` | 取整体生命体征 | 熵 1.2–2.6 且驻波比 >0.5 = 认知稳态 |
| `ripple_evolve(steps=20)` | 长时推演 | 看主构型是否漂移、熵是否上升 |
| `ripple_counterfactual({维: 态})` | 干预沙盘 | 熵降 = 干预使判断更清晰；熵升 = 干预放大不确定 |
| `ripple_immunity_query` | 经验覆盖度 | 命中率低说明该工况没历史，结论不可当成定论 |

## 三个必须输出的数（不是形容词）

1. **确定性**：场熵、驻波比、主构型概率。
2. **经验覆盖**：免疫库规模、近 7 天命中率、中和率。
3. **干预优先级**：按反事实的熵降幅度排序，不按"感觉严重程度"排序。

## 输出模板

```
【态势】产线主构型 体阴 变阴 因阴（概率 0.54），场熵 1.83，驻波比 0.88 → 认知稳态
【经验】免疫库 312 条，近 7 天命中 71%，中和 14%（在健康区间）
【风险】集中于 因（工艺成因）与 体（本体），变维连续 5 天为阴 → 劣化在加速
【沙盘】干预「因→阳」：熵 1.83→1.51（更清晰，首选）
        干预「势→阳」：熵 1.83→1.90（更模糊，不优先）
【建议】本周优先做工艺参数复核，而非加派点检人力
```

## 禁则

1. **禁止**用"感觉/大概率/应该"代替确定性数字。
2. **禁止**把熵升高解释成"系统坏了"——熵升高是"信息不足"的信号，正确处置是补证据，不是重启。
3. **禁止**在驻波比 <0.5 时给出优先级排序（此时场里没有稳定吸引子，排序无意义）。
4. **禁止**对外汇报使用"灵性/使命/数字生命"等词；统一说"经验分层与晋级"。
5. **禁止**替管理层下资源决策（如"停两条线"）。给排序与代价，决策权归人。

## 与其他两个 Skill 的分工

- 单台异常 → 设备异常诊断（要根因、要工单）。
- 批次/客诉 → 质量根因追溯（要责任环节）。
- 全局/跨设备 → 本 Skill（要确定性、要优先级）。
三者共用同一内核，**结论口径必须一致**（同一构型机器，不允许两个 Skill 给出不同卦名）。
