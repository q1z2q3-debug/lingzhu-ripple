# 验收方案与对照实验

> 原则：**不拿"感觉挺好"验收。** 每一分收益都要能被第三方复算。

## 一、四个必须回答的问题

| # | 问题 | 回答方式 | 判定 |
|---|---|---|---|
| Q1 | 判得准不准 | 历史工单回放，混淆矩阵 | 免疫命中准确率 ≥85% |
| Q2 | 有没有少打扰人 | 正常设备/正常工况的误报率 | 误报率下降 ≥40%（对基线） |
| Q3 | 有没有更快 | 从"读数到工单"的端到端耗时 | 中位耗时 ≤ 3 分钟（含人工确认） |
| Q4 | 结论能不能被复核 | 抽查结论是否带逐维证据链 | 100% 带证据 |

## 二、数据集构造（W2 前必须完成）

- **样本来源**：近 24 个月 EAM 工单 + 同期 SCADA 测点（时间对齐 ±10 分钟）。
- **标注**：每条工单最终根因由工艺/设备工程师复核，落 `verified=true`。
- **切分**：按**时间**切分，不随机切分。训练（前 18 个月）/ 测试（后 6 个月）。
  随机切分会把同一故障的相邻工单拆到两边，导致虚高——这是工业场景最常见的评测错误。
- **负样本**：等量正常工单（无异常处置记录），用于测误报。
- **规模下限**：每域 ≥300 条正样本 + 300 条负样本，低于此规模结论不可信。

## 三、对照设置（三组，同批样本）

| 组 | 配置 | 目的 |
|---|---|---|
| A 基线 | 现有灵助诊断（大模型 + 知识库检索） | 现网水平 |
| B 本包 | 涟漪认知场（免疫+相似+闸门） | 增量价值 |
| C 冗余 | 本包 + 灵助基线同时给结论，由闸门仲裁 | 验证"校验层"定位是否成立 |

指标：准确率、召回、误报率、平均处置时长、人工填写字段数、复核一次性通过率。

## 四、影子模式（W3，必做）

1. 系统只输出**提示与工单草稿**，派单仍由人执行。
2. 记录：系统结论 vs 人工结论 vs 最终实际根因（三方对比）。
3. 连续 2 周，样本 ≥100 条，Q1/Q2 达标 → 开派单权限；不达标 → 回到标定（改 warn/crit，不改内核）。

## 五、现场必测的四个边界用例

| 用例 | 期望 | 为什么必须测 |
|---|---|---|
| 全维正常 | `通过 / 运行状态正常`，不生成工单 | 防告警疲劳（早期版本此例误判"被中和"，属硬缺陷） |
| 空知识库 + 明显异常 | `被中和`，转人工，**不给根因** | 防编造（这是可信度的底线） |
| 复合故障（两个根因同分） | `待复核` + 并联处置，不单根因派单 | 防"只报一个"的假确定 |
| 反事实推演后复查 | 主场构型、熵完全不变 | 防推演污染状态（早期版本此处失真） |

这四条已固化在 `mcp/ripple_mcp_server.py --selftest` 与 `demo/demo_run.py` 中，可随时复跑。

## 六、上线后监控（MCP `ripple_field_status` 已提供）

| 指标 | 健康区间 | 异常含义 | 处置 |
|---|---|---|---|
| 场熵 | 1.2–2.6 | >2.6 认知弥散 | 该工况无历史相似，补种子 |
| 驻波比 | >0.5 | <0.5 无稳定吸引子 | 输入过杂或测点冲突，先收敛输入 |
| 免疫命中率 | >60% | 偏低 | 种子不足或 trits 生成不一致 |
| 中和率 | 10%–25% | >35% | 过度保守，查阈值/标定 |
| 单步耗时 | <5 ms | 超限 | 并发过高，需按设备分片 |

> 端到端中位耗时 X 分钟；影子期 2 周 118 条，人工一次性通过率 XX%。
